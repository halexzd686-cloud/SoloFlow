# SoloFlow 产品需求说明

> 状态：产品方向已确认，尚未进入代码实施
>
> 目标版本：本地网页 MVP

## 1. 产品定位

SoloFlow 面向完全不懂 AI、Agent 和 Vibe Coding 的公司员工。它帮助用户把自己反复做的工作，整理成一个可以持续使用、逐步修改并分享给同事的“工作助手”。

SoloFlow 的核心不是再提供一个通用聊天窗口，而是保存用户认可的工作方法，让同一类工作以后更稳定、更容易复用。

一句话描述：

> 把一次性的 AI 对话，变成可以持续使用的个人工作工具。

## 2. 目标用户与典型工作

### 2.1 目标用户

- 运营、销售、行政、人力、财务、客服、市场、项目等公司员工
- 能使用电脑和浏览器，但不了解提示词、Agent、工作流或 API
- 每周或每天都会重复处理一类输入和输出
- 希望减少整理、改写、汇总、检查和格式化工作

### 2.2 典型工作

- 根据本周工作记录生成周报
- 根据销售数据整理汇报表
- 将会议记录整理为结论、待办和责任人
- 按固定格式整理客户跟进信息
- 将一批材料改写成统一格式的文案
- 根据已有数据生成 Word、Excel、PDF 或 Markdown 交付物

这些只是示例。用户必须能够用自己的自然语言定义其他重复性工作。

## 3. 用户不需要理解的概念

面向用户的界面和文档统一使用以下业务语言：

| 技术概念 | 面向用户的名称 |
| --- | --- |
| Skill / Playbook | 工作助手 |
| Flow | 工作步骤 |
| Run | 本次任务 |
| Artifact | 结果文件 |
| Version | 工作助手版本 |

`skill`、`agent`、`flow` 等名称可以在内部代码和兼容层继续保留，但不应成为普通用户的主要操作语言。

## 4. MVP 目标

用户只需要复制一条命令启动 SoloFlow，然后在本地网页中完成以下闭环：

```text
启动本地网页
    ↓
配置 DeepSeek API Key
    ↓
选择示例助手，或用自然语言创建自己的助手
    ↓
补充表单并试运行
    ↓
保存为工作助手
    ↓
上传材料并手动运行
    ↓
敏感信息检查与发送确认
    ↓
预览、修改并下载结果文件
    ↓
按需保存新版本或分享给同事
```

## 5. 功能需求

### 5.1 启动与首次配置

- 第一版采用本地网页界面。
- 用户通过一条可复制的命令启动本地服务并打开网页。
- 启动命令自动检查 Python、依赖和必要目录。
- 缺少环境或依赖时，使用普通语言给出处理提示。
- 首次进入时引导用户填写 DeepSeek API Key，并测试连接。
- API Key 仅保存在本机，不进入工作助手导出包、运行记录或生成文件。

### 5.2 首页与示例助手

首页应让用户立即理解 SoloFlow 能做什么，至少提供若干示例助手，例如：

- 周报整理
- 表格汇总
- 会议内容整理
- 销售跟进整理

示例助手用于教学和快速体验，不限制用户创建其他类型的助手。

### 5.3 创建工作助手

创建过程采用“自然语言 + 自动整理表单”的方式：

1. 用户描述自己反复做的工作。
2. SoloFlow 提取工作目的、输入材料、处理步骤、输出结果、格式要求和注意事项。
3. 用户在简单表单中确认或修改这些内容。
4. 用户可以补充一条临时要求或上传示例材料。
5. 必须先试运行并预览结果。
6. 用户确认后，才能保存或分享工作助手。

表单不应要求用户编写 Prompt 或配置 YAML。系统内部可以将确认内容保存为可执行的工作助手定义。

### 5.4 运行工作助手

- 第一版只支持用户手动点击运行，不做定时任务和后台自动执行。
- 用户可以输入文字、粘贴内容或上传文件。
- 用户可以在本次运行中提出新的临时要求。
- 临时要求默认只影响本次任务，不自动修改长期助手。
- 用户明确确认长期修改后，才生成新的工作助手版本。
- 每次运行前允许切换 DeepSeek 模型。
- 工作助手可以保存默认模型，但分享时不包含 API Key。

### 5.5 输入文件

第一版支持：

- Word：`.docx`
- 表格：`.xlsx`、`.csv`
- PDF：`.pdf`
- 文本：`.txt`、`.md`

第一版暂不支持图片、扫描件和 OCR。待 DeepSeek 官方 API 提供可直接读取图片的视觉模型后，再重新评估图片输入。

### 5.6 隐私检查与 DeepSeek 发送确认

SoloFlow 默认坚持：运行记录和生成文件保存在本地，必要内容发送给用户配置的 DeepSeek 服务。

每次运行涉及外部模型请求时，必须明确告知用户：

- 哪些内容将发送给 DeepSeek
- 发送可能产生 API 费用
- 用户需要判断材料是否敏感

建议流程：

```text
本地检查材料
    ↓
提示可能存在的手机号、邮箱、身份证号、客户名称等敏感信息
    ↓
询问“是否按照建议修改，还是您手动修改后重新上传？”
    ↓
按建议生成独立的脱敏副本，原始文件保持不变
    ↓
用户确认后，才发送给 DeepSeek
```

扫描只能提供风险提示，不能承诺识别所有敏感信息。用户应始终拥有取消、重新上传和继续发送的决定权。

### 5.7 结果预览与文件交付

结果交付采用：

```text
生成 → 预览 → 自然语言修改 → 确认 → 下载
```

要求：

- 生成结果先在网页中预览，不直接强制下载。
- 用户可以继续用自然语言要求修改。
- 支持用户指定输出格式；未指定时必须询问最终需要的格式。
- 支持 Word、Excel、PDF、Markdown 等常见结果格式。
- 一次生成多个文件时，每个文件提供单独下载。
- 同时提供 ZIP 打包下载。
- 原始输入、结果文件和历史版本分开保存。

### 5.8 工作助手版本

- 本次运行的临时修改不改变长期助手。
- 用户确认长期修改后生成新版本。
- 旧版本保留，可查看、恢复和重新分享。
- 分享时必须明确分享的是哪个版本。

### 5.9 分享与导入

用户可以一键导出工作助手文件，同事导入后得到自己的可编辑副本。

导出包可以包含：

- 工作目标
- 输入字段
- 工作步骤
- 输出格式
- 写作风格和规则
- 默认模型偏好
- 版本信息

导出包不得包含：

- 原始工作文件
- 脱敏前后的个人或公司数据
- 运行历史
- 生成结果文件
- API Key

第一版不做多人在线共享、统一维护、权限管理和强制版本同步。

### 5.10 本地记录管理

- 运行记录和生成文件默认保存在本机。
- 用户可以删除单次运行记录。
- 用户可以删除某个助手的历史文件。
- 用户可以一键清空本地数据。
- 第一版不自动上传云端，也不自动删除历史。

## 6. 明确不纳入 MVP 的内容

- SoloFlow 账号、会员和套餐
- 多人在线协作和权限管理
- 飞书、钉钉、企业微信、邮箱、网盘等外部平台连接
- 自动定时任务和后台执行
- 扫描件和 OCR
- fallback model
- 持久化队列和分布式执行
- 自动调用浏览器、搜索引擎或本地外部工具
- 将 MCP 作为普通用户入口
- Cursor 和 Codex 的专门兼容性验证

## 7. 验收场景

### 周报助手

用户说：“我每周要提交周报，固定包含本周完成、未完成、问题和下周计划。”

SoloFlow 应生成可编辑的助手草稿。用户确认后，上传本周材料，选择输出格式，完成敏感信息确认，运行并预览周报。用户提出“把问题部分写得更适合给领导看”，系统只修改本次结果；用户明确确认后，才把该要求保存为新版本。

### 助手分享

用户将周报助手导出给同事。同事导入后得到个人副本，可以把“适合给领导看”改为自己的表达方式，且不会影响创建者的助手、数据和历史记录。
